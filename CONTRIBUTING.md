# Contributing to Westernis

Thanks for your interest! Bug reports, fixes, new entity types, theme improvements and
documentation are all welcome. Please read the [Code of Conduct](CODE_OF_CONDUCT.md) first,
and report security problems privately as described in [SECURITY.md](SECURITY.md).

Code, comments, commit messages and issues are in English. The wiki's interface and its sample
content are German (see [German text, English identifiers](#german-text-english-identifiers)).

## Development setup

You need Docker with Compose v2, PowerShell 7 (`pwsh`, available for Windows, macOS and Linux:
<https://aka.ms/powershell>) and Node.js 22 or newer.

```sh
git clone https://github.com/shiftbloom-studio/westernis.git
cd westernis
pwsh ./scripts/wiki.ps1 init        # creates .env with fresh random secrets
pwsh ./scripts/wiki.ps1 up          # builds the image, starts the stack, seeds the wiki
npm ci --prefix tools/forge-mcp     # the MCP server (needed for Claude Code and the tests)
npm ci --prefix tools/brand         # only if you work on the generated artwork
```

The wiki then runs at <http://localhost:8088>. `pwsh ./scripts/wiki.ps1 sync` pushes edits to
`LocalSettings.php`, `wiki/assets`, `scripts` and `content` into the running containers;
`pwsh ./scripts/wiki.ps1 seed` re-imports the seed pages. See the [README](README.md) for all
commands.

## Generated files: edit the generator, not the output

Many files are generated. Never edit them by hand; change the source and re-run the generator.

| Output | Source | Command |
| --- | --- | --- |
| `content/pages/Template/Infobox_*`, `Template/Skeleton__*`, `Form/*`, entity `Category/*`, `Project/Create.wiki`, `Module/Westernis__labels.lua`, `tools/forge-mcp/schemas.json` | `tools/gen-entities/entities.js` (types and fields), `tools/gen-entities/de.js` (German labels) | `node tools/gen-entities/generate.js` |
| Sample articles (`content/pages/Main/*` except `Main_Page` and `Weltkarte`), `Chronicle/*`, `Help/*`, `Project/*` (except `Create`), housekeeping categories | `tools/gen-entities/samples.js` | `node tools/gen-entities/samples.js` |
| `wiki/assets/img/hero/*`, `img/orn/*`, `img/icons/*`, `img/divider-*`, brand wordmark, tagline and logo | `tools/brand/make-*.js` | `npm run svg --prefix tools/brand` |
| `content/files/Westernis_map.svg` and `.webp` | `tools/brand/make-map.js`, `raster-map.js` | `npm run all --prefix tools/brand` |

`generate.js` does not run `samples.js`; run both after changing `tools/gen-entities`. Commit the
generated output together with the source change. CI fails when they are out of sync. The other
templates (`Quote`, `Drop_cap`, `Timeline*`, `Family_tree`, …), `Module/Family.lua`,
`Module/Westernis.lua`, `Main/Main_Page`, `Main/Weltkarte`, `Map/Westernis.json` and everything
in `content/pages/MediaWiki/` are hand-written.

## German text, English identifiers

- Reader-facing text in the wiki (labels, group headers, section titles, dropdown display values,
  type names) is German. For generated pages it lives in `tools/gen-entities/de.js`; the
  generator fails on any untranslated label.
- Identifiers stay English: template, form, table, field and category names, page titles of the
  sample pages, and stored dropdown values. That keeps data, links and tooling stable.

## Content rules

- Never change facts on pages marked `canon=Tolkien`. New lore starts as `canon=Draft`.
- Summarise Tolkien in your own words. No long verbatim quotations from the books or their
  translations; short quotations are fine when attributed (work, book, chapter).
- No personal data in pages, screenshots or examples.

## Theme and artwork

- The design system is `content/pages/MediaWiki/Common.css`, the skin chrome
  `content/pages/MediaWiki/Citizen.css`, effects `wiki/assets/js/westernis.js`. Re-seed after
  editing the `MediaWiki/` pages.
- Artwork is generated by `tools/brand` and is deterministic; do not hand-edit the SVGs.
- `/assets` is cached by browsers for a day: bump the `?v=` on changed images in `Common.css`,
  and `WST_ASSET_VERSION` in `LocalSettings.php` after changing `westernis.js`.
- Include screenshots of night and day mode in pull requests that change the look.

## Checks

These mirror [CI](.github/workflows/ci.yml) and need neither Docker nor a running wiki:

```sh
node tools/gen-entities/generate.js && node tools/gen-entities/samples.js
git status --porcelain                    # must be empty after the generators ran
for f in tools/forge-mcp/src/*.js tools/forge-mcp/test/*.js tools/gen-entities/*.js \
         tools/brand/*.js wiki/assets/js/*.js content/pages/MediaWiki/*.js; do node --check "$f"; done
npm test --prefix tools/forge-mcp          # offline MCP server test
pwsh -NoProfile -Command '$e=$null; [void][System.Management.Automation.Language.Parser]::ParseFile("$PWD/scripts/wiki.ps1",[ref]$null,[ref]$e); if ($e) { $e; exit 1 }'
```

Tests that talk to a running wiki **write to it** (they create pages under `Notes:`), so run
them only against your own local wiki:

```sh
npm run smoke --prefix tools/forge-mcp       # API client: login, edit, read back
npm run test:live --prefix tools/forge-mcp   # drives every MCP tool once
```

Do not run a bare `node --test` in `tools/forge-mcp`: it would also pick up the live test.

## Secrets

`.env` holds every password and key and is git-ignored, and so is `backups/` (each backup
contains a copy of `.env`). Never commit either, and never paste their values into issues.
Per-install PHP overrides go into the untracked `wiki/LocalSettings.local.php`.

## Pull requests

1. Fork, create a branch, keep the change focused.
2. Run the [checks](#checks) and, for wiki-facing changes, try it on your local wiki.
3. Fill in the pull request template.
